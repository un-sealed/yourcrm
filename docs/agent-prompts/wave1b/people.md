# Wave 1b — People Module (THE GOLDEN REFERENCE)

Branch: `agent/people`

This is the most consequential module in the project. **Eleven later agents
are instructed to read your code and mirror it exactly** for Companies, Leads,
Deals, Pipelines, Activities, Tasks, Products, Forms, Files, Search and
Import/Export.

Every good decision you make is copied eleven times. So is every bad one.
Favour clarity and consistency over cleverness — a pattern a weaker model can
follow correctly is worth more than an elegant one it will misread.

Spec: `docs/yourcrm-agent-spec-pack/06-people.md`

## The seams already exist — use them, never rebuild them

These landed this week. Read them before designing anything.

**`@yourcrm/ui`** — the full design system. Import, never re-implement:
`DataTable`, `FilterBuilder`, `SavedViews`, `BulkBar`, `RecordHeader`,
`Timeline`, `EmptyState`, `ErrorState`, `Skeleton`, `ConfirmDialog`, `Dialog`,
`Field`, `TextField`, `TextArea`, `Select`, `Checkbox`, `DatePicker`,
`Combobox`, `Badge`, `Avatar`, `Tabs`, `toast`.
Read `packages/ui/README.md` for prop signatures. If a primitive is missing or
wrong, **report it — do not build a local copy.**

**`@yourcrm/testing`** — use these instead of hand-rolling fixtures:
`makeSession`, `makeWorkspace`, `makeUser`, `makeMembership`,
`makeServiceContext`, `makeBaseRecord`, `expectDenied`, `expectAllowed`,
`captureEvents`, `createApiClient`, `freezeTime`, `createIdGenerator`.
Read `packages/testing/README.md`.

**`writeAudit(db, input)`** from `@yourcrm/database` — the audit contract.
Call it on every mutation. Do not write to `audit_events` directly.

**Route registry** — `apps/api/src/routes/modules/`. Add your file there;
`apps/api/src/routes/v1.ts` picks it up. Follow
`apps/api/src/routes/modules/system.ts` as the shape example, and run
`bun run gen:routes` if the manifest needs regenerating. **Never edit `v1.ts`.**

**Shared tables** — tags, relationships, custom fields and saved views already
exist with repositories in `packages/database/src/repositories/`. Wire to them.
Do not create your own tagging or relationship tables.

**Auth** — real sessions exist. `requireSession()` works; `/api/v1/me` returns
a real user. Seeded logins: `admin@yourcrm.local` / `Password123!`.

## Scope — P0, and make it exemplary

- `people` table + `person_emails`, `person_phones` (multiple per person,
  one primary each)
- Service layer in `packages/crm/src/people/`: `list`, `get`, `create`,
  `update`, `softDelete`, `restore`. Every method:
  1. `requirePermission()` **first**, before any read or write
  2. do the work through the repository
  3. emit the domain event via the `CrmEvents` constant
  4. `writeAudit()` with before/after
- API routes: zod validation at the boundary, shared envelopes from
  `@yourcrm/validation`, cursor pagination, correlation ID passthrough
- Web: list page with `DataTable` + `FilterBuilder` + `SavedViews` + `BulkBar`,
  detail page with `RecordHeader` + `Timeline`, create/edit form, plus
  `loading.tsx` and `error.tsx`
- Tests: service unit tests, API tests, **and a denial test using
  `expectDenied`**, plus an event assertion using `captureEvents`

Out of scope — later agents: merge/duplicate detection, import/export, AI
features, enrichment, consent/GDPR, automation triggers.

## Hard rules

- Never `bun add` or edit any `package.json`. Report a missing dep instead.
- Cross-module references (`company_id`) are plain `uuid` columns with an
  index and **no foreign key** — those tables do not exist yet.
- No business logic in route handlers. No SQL outside `packages/database`.
- `packages/crm` must not import Hono, Next.js, React or `@yourcrm/ui`.
- Event names come from the `CrmEvents` constant, never string literals.

## Definition of done

```bash
bun run typecheck && bun run lint && bun run test && bun run build && bun run db:migrate
```

All must pass; lint with zero warnings. No `any`, `eslint-disable`,
`@ts-ignore` or `.skip()` to get there.
